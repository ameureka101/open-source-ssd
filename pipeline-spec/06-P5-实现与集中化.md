## P5 实现与集中化（{{PROJECT}} 当前执行版）

> 状态：v0.5 · {{PROJECT}} 实战回写 · 2026-06-07  
> 当前结论：P5 已完成一轮可运行实现，且追加完成 P5.1 桌面视觉复刻修正。本文取代旧 pixel-labs 实现假设，作为 {{PROJECT}} 后续站点实现的当前标准。

P5 的任务不是“把 Stitch 的 `code.html` 放进路由”，而是把 P3/P4 冻结出的内容、视觉、工程约束，落成一个可运行、可验证、可继续维护的 Next.js 站点。{{PROJECT}} 当前采用的原则是：

1. **Stitch HTML 是只读蓝图**：可读结构和视觉关系，不复制生产代码。
2. **视觉真理以统一后的桌面蓝图为准**：当前基准在 `content/design/output/unified_blueprints/`，不是原始多风格导出。
3. **本地实现必须集中化**：SEO、表单、视觉 token、共享组件、路由壳都要有单一来源。
4. **先有负向断言，再做实现收敛**：`anti-slop`、lint、build、截图、curl 都是 P5 的组成部分，不是 P7 才补。

### 4. P5 标准执行顺序

1. **冻结蓝图**
   - 原始 Stitch 导出先进入 `content/design/output/`。
   - 多页风格不一致时，先统一成 `unified_blueprints/`。
   - 生成 `reference_render/` 桌面截图，作为后续对照。

2. **建立负向断言**
   - 禁止复制 `cdn.tailwindcss.com`、Material Symbols、MD3 token、旧模板词。
   - 禁止明显 anti-slop 视觉：无意义渐变、阴影、圆角胶囊、hover scale、纯黑等。
   - `rg` 不在 PATH 时必须 fallback 到 `grep` 或硬失败，不能静默通过。

3. **统一视觉 token 与壳**
   - 以 Stitch 统一蓝图的实际视觉值为准。
   - 对 {{PROJECT}} 当前 FG 体系，核心色应围绕 `#222222`、`#F0EFEA`、`#D4930D`、`#E7B04A`。
   - 保留本地组件依赖的 token 名，但值要映射到当前视觉系统。

4. **重写页面实现**
   - 不复制 `code.html`。
   - 以本地组件、消息、配置和 token 重写页面。
   - 页面数据层尽量不动，优先改渲染层。

5. **集中 SEO 与表单**
   - 页面 metadata 统一从 registry 派生。
   - 表单走 Server Action。
   - webhook、密钥、生产域名通过环境变量注入。

6. **截图对照与微调**
   - 先 1280px 桌面逐页对齐，再做 320px 溢出验证。
   - 视觉对齐不是只看“风格相似”，要看字体、线条、背景色、块高、留白、动态图形和图标占位。

### 5. P5 验证命令

在 `template/` 下执行：

```bash
pnpm anti-slop
pnpm lint
NEXT_PUBLIC_BASE_URL=https://{{PRODUCTION_DOMAIN}} BETTER_AUTH_SECRET={{PROJECT_SLUG}}-production-build-check-secret pnpm build
```

本地运行后补：

```bash
curl -s http://localhost:3000/sitemap.xml
curl -s http://localhost:3000/robots.txt
curl -s http://localhost:3000/manifest.webmanifest
```

表单要用浏览器或 Playwright 提交验证，不只看类型通过。

### 6. 当前 known-traps

- **KT-030 多蓝图分属不同设计系统**：Home 与其他页可能来自不同 Stitch 风格，必须先统一蓝图层，再实现。
- **KT-031 设计文档 ghost truth**：文档声称的 token 与实际蓝图冲突时，以蓝图和当前实现核验后的真值为准，并反向修正文档。
- **KT-032 Stitch 原始产物含违规词**：`Login`、`Get Started`、`Security`、`System Status`、固定年份等不能进入公开 shell。
- **KT-033 light-only 站点的 dark token 漂移**：如果 MVP 不提供主题切换，dark token 应镜像或禁用，不能维护另一套未审视觉。
- **KT-034 Server Action redirect 被 try/catch 吞掉**：提交成功后的 `redirect()` 不要包进会吞异常的 catch 逻辑。
- **KT-035 风格相似不等于像素复刻**：通过 anti-slop 和 build 只能说明工程可用，不能说明视觉接近；必须截图对照。
- **KT-036 移动端不是 P3B 阻塞项，但必须在 P5/P7 验证**：P3 可以只产桌面蓝图，P5 必须补 320px 横向溢出检查。
