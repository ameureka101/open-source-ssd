### 4. 熵审计问题清单

每次收尾时问：

1. 文档说的路径是否真实存在？
2. 文档说的阶段状态是否已经过期？
3. 文档是否仍引用旧项目名、旧域名、旧技术栈、旧路由数量？
4. 实现是否已经推进，但 pipeline 还说“尚未开始”？
5. 是否有“原文”文件被误当当前执行标准？
6. 是否有生产模拟验证被误写成生产完成？
7. 是否有 P3 桌面蓝图约束被误扩展成必须输出移动蓝图？
8. 是否有 CCAF/CPN 合规措辞在文档、metadata 或页面中漂移？

发现任一项，要么修正文档，要么标注为历史参考，不能让它继续作为活规则。

---

### 5. 推荐 write-back 格式

在 memory 中使用短事实文件：

```text
.claude/memory/{{PROJECT_SLUG}}-<stage>-<topic>-<date>.md
```

每条事实至少包含：

- 日期。
- 完成了什么。
- 证据路径。
- 验证命令。
- 残留风险。
- 后续触发条件。

在 `PROJECT.md` 中只写稳定事实，不写长过程。

在 pipeline 文档中写可复用方法，不写一次性聊天记录。
