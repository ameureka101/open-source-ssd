## 品牌与设计方向确立（Brand & Design Direction）

> 受 {{PROJECT}} AGENTS.md §2 约束：禁止仿制 the AI provider 的视觉与品牌语言；本阶段产出的任何对外口径在发布前必须经人审；合规边界（Partner 身份、认证、KPI 绝对值）不得在本阶段越界。
>
> **关键说明**：这是 pixel-labs 真实测绘里被**省略**的探索环节——pixel-penguin 起步时直接以"已定的 `Anti-Slop Brutalist` 哲学 + Cold Architect 嗓音"为前提，没有交代这套方向是怎么从 0 得到的。对任何**新站**，本阶段是必经工序；它的输出是后续 P2（设计真理沉淀 tokens/components/pages）和实现层一切派生物的过滤器。本节把 pixel-labs 已沉淀的成品（README 的允许/禁止清单、english-copy 的 Cold Architect 15 条）反推为"如何确立"的可复用方法。

---

### ① 目标

用**两个专名**把模糊的审美意图压成可机器/人工核对的硬约束，作为下游所有设计与文案的唯一过滤器：

1. **一个名词定义品牌嗓音（Brand Voice）**——给文案一个带立场的人格代号（pixel-labs 用 `Cold Architect`：直接、对抗式、技术具体、零 hedge 词）。它的作用是：任何一句文案都能被问"这句话符合这个嗓音吗？若它能出现在任意咨询公司官网，就重写"。
2. **一个带立场的设计哲学专名（Design Philosophy）**——给视觉一个**反某某**式的主张（pixel-labs 用 `Anti-Slop Brutalist SaaS`：拒绝 AI 塑料感、追求印刷品质感）。立场性是关键：哲学名本身就是决策过滤器，任何元素都能被问"它符合/违反这个哲学吗"。
3. 把上述两个抽象专名**落成二元"允许 / 禁止"清单**——视觉清单（允许：巨型排版/大留白/非对称 Bento/颗粒噪点/深浅交替/1px 细线；禁止：渐变/圆角>2px/阴影/hover 浮起/入场动画/装饰图标/emoji/默认字体/h-screen）+ 文案清单（允许：对抗式标题/结果优于功能/证据优于承诺；禁止：通用企业腔/hedge 词/无证据承诺/Partner 与认证的过早声称）。

本阶段**不产出** tokens 色值表、组件规范或页面稿——那是 P2 的事。本阶段只锁"方向与边界"。

### ② 输入

- P0 内容真理层的元数据头 6 坐标（产品类型 / 目标 / 受众 / 技术栈 / 设计体系占位 / 品牌占位）——本阶段负责把"设计体系"和"品牌"这两个占位**填实**。
- 受众与定位事实（pixel-labs：年营收 $10M+ 的 2B 客户、企业级 AI 咨询）。
- 竞品/参照视觉的调研结论（用于决定"反对什么"——这是 gap，新站必须现做，pixel-labs 测绘里缺失）。
- 合规边界清单（{{PROJECT}} §2：不得仿 the AI provider 视觉；Partner 未获批不公开；认证 readiness 不写为已认证；KPI 公开面只给方向值/标 NDA）。
- 既有品牌资产（若有）：Logo/字标存放约定 `_docs/<PROJECT>_ASSETS_VAULT/04_Brand_and_Domain/Logos/`，文档只引用不内嵌。

### ③ 输出交付物（门控产物）

| 交付物 | 内容 | 角色 |
|---|---|---|
| **设计哲学声明 + 允许/禁止清单**（视觉） | 哲学专名 + 核心主张一句话 + 二元清单 | 视觉真理的"宪法"，P2 tokens/components 必须可回溯到它 |
| **品牌嗓音定义 + 文案规则**（文案） | 嗓音名词 + 反例→正例对照表（pixel-labs 为 P0-P5 共 15 条；新站可精简为 P1-P3） | 文案真理的"宪法"，所有 UI 文案与 content 成品稿派生于它 |
| **品牌速查表** | IP/吉祥物（可选）/ 主色方向 / 字体角色方向 / 标志性质感 / 哲学一句话 | 跨文件对齐的单页参照 |
| **合规口径基线** | Partner 措辞、认证措辞、KPI 措辞的"允许/禁止"样例 | §2 合规门控的判据 |

落地位置（pixel-labs 真实做法，新站照搬）：写入 `content/design/README.md`（设计哲学+允许/禁止清单）与 `_working-going/<brand>-copy-principles-<date>.md`（嗓音 15 条）。这两份文件即本阶段的**门控产物**，未签署不得进入 P2。

### ④ 用什么 skill + 工具 + 命令

- **`brand-strategy-design`**（主力）：产出品牌定位、受众、视觉识别方向、嗓音。
- **`competitor-analyzer`**：先做参照视觉/口径调研，确定"反对什么"——立场性专名的来源。
- **`fpf-reasoning` / `spec-dev` 的 review 维度**（可选）：把"哲学专名 + 嗓音"作为一个决策，用 R_eff 给方向成熟度打分，产出 DRR（决策记录），作为人审门控前的量化证据。
- **`prompt-optimizer`**：把"嗓音"固化成可复用的文案改写指令模板。
- **验证命令**（本阶段就要先建立"嗓音禁词扫描"的雏形，供后续 gate 复用）：
  ```bash
  # 嗓音负向断言：通用企业腔禁词应为 0 命中（KT-025 的判据来源）
  rg -i 'Navigating|the Frontier|Book a Consultation|We help enterprises|focused on' messages/ content/
  # 合规负向断言：Partner / 认证过早声称应为 0（KT-028 / §2）
  rg -i 'AI Partner|certified|SOC ?2 (certified|compliant)' messages/ content/ public/
  ```

### ⑤ mk-saas 落地映射（本阶段产物对应改哪些文件）

> 说明：pixel-penguin **未采用** mk-saas（已被证伪）。但本 pipeline 面向**基于 mk-saas 的新站**，故按 mk-saas 模板真实结构给映射（已核对 `_opensource/mksaas-template-main/`）。本阶段只写"方向与约束"，落到 mk-saas 的"配置/全局"层，**不碰页面组件**。

| 本阶段产物 | mk-saas 落地文件 | 改什么 |
|---|---|---|
| 品牌名 / 字标 / 元数据 / 主题色方向 | `src/config/website.tsx` | 站点品牌字段、`metadata`、`theme`（暗/亮、品牌主色变量名）的方向值；这是 mk-saas 的品牌单一来源 |
| 设计哲学 → 设计变量方向（仅"方向"，具体值留 P2） | `src/styles/globals.css` | 在 `@theme`/CSS 变量层预留品牌色板、圆角（哲学若反圆角则全置 `0`）、字体角色变量的占位与注释；不在本阶段填全套色阶 |
| 品牌嗓音 → UI 文案口径 | `messages/en.json` 为源，`messages/zh.json` 等其余 locale 继承 | 仅锁定 hero/CTA/导航等"高曝光文案"的嗓音方向样例；全量文案是后续阶段 |
| 设计哲学声明 + 允许/禁止清单（文档真理） | `content/`（mk-saas 用 fumadocs `content/`）或新增 `content/design/README.md` | 写入哲学+清单，作为 design-generation source of truth |
| Logo / OG / favicon 资产 | `public/`（如 `public/logo.png` / OG 图） | 放置占位或终版品牌资产；文档只引用路径不内嵌二进制 |
| 合规口径基线 | `src/config/website.tsx` 的描述字段 + `messages/*.json` | 确保 Partner/认证/KPI 措辞符合 §2，禁词扫描 0 命中 |

> mk-saas 的 i18n 是 `messages/{locale}.json`（next-intl 命名空间），与 pixel-penguin 的单文件 `dictionaries.ts` 不同——本阶段只需确立"en 为源、其余 locale 继承"的原则，具体翻译落地在后续 i18n 阶段。

### ⑥ 人审门控

本阶段是整个 pipeline 中**人审权重最高**的环节之一，因为方向一旦错，下游全部返工。门控条目：

1. **方向签署**：哲学专名 + 嗓音名词 + 两份允许/禁止清单，须由项目 owner 明确签署"以此为准"，写入门控产物文件头。
2. **§2 合规复核**（强制人审，不可自动化）：
   - 视觉方向**不得**与 the AI provider 的品牌视觉构成仿冒（配色/版式/吉祥物不得致敬式抄袭）；
   - 文案口径**不得**出现 Partner 身份/认证的过早或绝对声称；
   - KPI 公开口径只允许方向值（如 `+55%`）或标 `metrics under NDA`，禁绝对承诺/SLA 数字。
3. **品牌实体一致性核对**：创始人对外公开名、公司名、域名在所有产物中统一（pixel-labs 踩过 `Ethan Chang` vs `Yichuan Zhang` 不一致的坑）。
4. **禁词扫描通过**：上文两条 `rg` 命令 0 命中，作为人审前的客观判据。
5. 未通过门控**不得进入 P2**（设计真理沉淀）。

### ⑦ 本阶段相关的 known-traps

- **KT-025 英文文案退回通用企业腔**：嗓音定义不落成"反例→正例对照表 + 禁词清单"时，后续极易回退到 `Navigating the Enterprise AI Frontier` / `Book a Consultation` 这类 slop。对策：本阶段就把禁词 `rg` 扫描固化为可复用 gate。
- **KT-028 Partner 身份过早公开**（直接对应 §2）：方向稿/口径里不得出现 `AI Partner` 等表述，未获批前只能用"implementation firm / application in progress"；用 `rg` 扫公开面应 0 命中。
- **"the AI" 污染（P0 级，english-copy 原则首条）**：全局 find-replace 会把品牌/技术词误伤成破英文（`Enterprise the AI Implementation`）。本阶段确立嗓音规则时必须同时写明"品牌词 vs 冠词+名词"的合法例外，并给 `grep -c` 量化判据，避免下游照抄污染。
- **强调色滥用塌成普通 SaaS**：高端感的隐形门槛是"强调色极度克制"。本阶段确立色彩方向时必须写死"单一克制强调色、仅 Primary CTA 使用"，否则 P2 落色时易失控。
- **设计哲学专名缺立场 = 无效过滤器**：若专名只是形容词堆砌（"现代简约高级"）而非"反某某"的二元立场，它无法在下游充当"允许/禁止"的判断锚——这是本阶段最隐蔽的失败模式。
- **品牌实体跨文件不一致**：创始人/公司/域名在规划稿与对外稿里不统一，会在 i18n/SEO 阶段集中爆发，须在本阶段一次锁定。
- **生成工具会注入自己的设计体系**（前瞻提醒，KT-001 的根因）：本阶段确立的"禁默认字体/禁组件库默认视觉"清单，是后续防止 Stitch/模板把 Material Design token、CDN 图标字体当生产代码的源头约束——清单越早写死，下游剥离越省力。
