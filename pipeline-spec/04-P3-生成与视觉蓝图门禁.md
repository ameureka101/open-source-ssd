## 1. 阶段定位

P3 不是“写完 Stitch prompt 就结束”。P3 是把文字规格转成可审画面，并证明画面可以被工程复刻。

本阶段分两道门：

| Gate | 名称 | 目标 | 通过后才能 |
|---|---|---|---|
| P3A | Blueprint Prompt Prep | 准备可生成页面的自包含 prompt | 执行 Stitch 出图 |
| P3B | Visual Blueprint Gate | 生成桌面页面图、审查并回写 | 进入 P4 spec |

每个页面包标准内容：

| File | Required | Meaning |
|---|---|---|
| `screen.png` or `screen-desktop.png` | Yes | 桌面端视觉蓝图 |

| `review.md` | Yes | 视觉、合规、移动端、工程可复刻审查 |
| `revision-notes.md` | If needed | 微调指令与回写记录 |

## 5. 审查维度

| Dimension | Pass condition |
|---|---|
| 信息层级 | 10 秒内能理解页面主目标 |
| 品牌一致性 | 符合 Ink & Paper with Beacon Amber Accent |
| 合规边界 | 不暗示官方身份，不写 locked facts |
| 移动端可读性 | P3B 可记录风险；P4/P7 本地实现必须验证 320px 不溢出、不横向滚动 |
| 工程可复刻 | 能用 mk-saas / shadcn / Tailwind token 重写，不依赖 Stitch 代码 |
| 模板污染风险 | 不把 Material Symbols、MD3 token、CDN Tailwind 带入生产 |

## 7. 回写规则

P3 审查发现的问题不能只停留在 `review.md`。

必须按影响面回写：

| Finding | Write back to |
|---|---|
| 文案或事实风险 | `content/` 或 `content/_fact_check/` |
| 页面 section 顺序不合理 | `content/design/page_specs/*-v0.2.md` |
| prompt 描述不精确 | `content/design/stitch_prompts/*.txt` |
| token / component 规则不足 | `content/design/design-tokens.md` 或 `components.md` |
| 工程实现约束 | P4 site spec |

## 8. P3 通过条件

P3B 通过前，不能进入 P4。

必须满足：

- Home、Guide、Bootcamp、Enterprise 各有桌面图。
- 每个页面包有 `review.md`。
- `REFINE` 或 `FAIL` 的问题已有 `revision-notes.md`。
- 审查后的结构调整已回写 `content/design/page_specs/`。
- `code.html` 被明确标注为只读参考，不进入生产代码。
- 英文标签、Subscribe、placeholder 可作为 P4 messages cleanup，不阻塞 P3B。

## 10. Known Traps

- **KT-001 把 Stitch HTML 当生产代码**：`code.html` 只能作结构参考；生产代码必须回到本地 token 和组件重写。
- **KT-002 改 prompt 不改源链**：prompt 里的文案和事实必须能追回 `content/`，不能临时改。
- **KT-004 视觉修复引入 token 漂移**：纠偏时只允许用已命名 token；不要临时加 HEX、阴影、渐变、大圆角。
- **移动端职责错位**：P3B 不强制移动截图，但 P4/P7 必须检查 320px，不使用 uppercase、过宽 letter-spacing、长 mono 标签。
- **过早进入 P4**：没有图就写工程 spec，会把页面节奏和组件密度留给实现阶段临场猜。
