# P4 规范驱动工程收敛规划

> 阶段：P4 Spec-Driven Implementation Planning
> 状态：v0.5 {{PROJECT}} 修正版（2026-06-07 补状态）
> 上游：P3B 桌面视觉蓝图 + `content/design/page_specs/*-v0.2.md`
> 核心修正：P4 不是写代码，也不是继续调 Stitch；P4 是把“要实现什么、改哪些文件、禁止带入什么、怎么验证”写成工程可执行规格。
> 当前补充：P4 五件套已支撑 {{PROJECT}} 进入 P5/P7；后续不再把 P4 当待启动阶段，而是作为实现边界和回归审计依据。当前公开范围冻结为 `/`、`/guide`、`/bootcamp`、`/enterprise`。

## 1. P4 是什么

P4 是从“设计蓝图”进入“生产实现”前的收敛层。它回答四个问题：

1. **模板现实是什么**：mk-saas 模板或目标工程里实际有哪些页面、配置、messages、组件和残留文案。
2. **目标现实是什么**：{{PROJECT}} 的内容真理、设计真理、P3B 蓝图和 page specs 要求什么。
3. **差距怎么改**：逐文件列出新增、删除、替换、隐藏、重写和验证任务。
4. **什么情况下不许开工**：把合规、文案、品牌、Stitch 污染、模板残留、Owner 决策和 Git 安全写成 Implementation Gate。

一句话：**P4 产出施工图，不施工。**

## 3. P4 输出五件套

建议落点：

```text
content/design/implementation_specs/p4-template/

├── 01-requirements.md
```

| File | 必须回答 |
|---|---|
| `00-discovery.md` | 目标工程/模板真实结构是什么；模板残留有哪些；Git/敏感文件状态是否安全 |

| `03-tasks.md` | 可执行任务清单，按 Guardrails -> Shell -> Tokens -> Pages -> Forms -> Verification 排序 |
| `04-implementation-gate.md` | 开工门禁、阻塞项、人审项、验证命令和通过标准 |

## 4. P4 Preflight

生成五件套前，先做 P4 preflight。它不属于 P5，不改生产代码，只确认 P4 能正常开始。

| Check | Required output |
|---|---|
| Git baseline | 当前仓库必须在 `main` 分支；P5 前必须有 baseline commit，或在 `04-implementation-gate.md` 记录不提交的显式例外 |
| Target engineering decision | 明确采用 `mk-saas` 模板、fresh Next.js app、或其他目标工程；不得一边写 P4 一边猜 |
| Target path | 冻结目标路径，默认 `template/` |
| P3B status | 确认 `P3-output核实记录-v0.2.md` 和 4 个 `page_specs/*-v0.2.md` 已回写 |
| PENDING inventory | 从 `messages-map` 与 `website-config-map` 提取所有 `PENDING`，分成 safe default / Owner decision / non-scope |
| Sensitive ignore | `.gitignore` 已覆盖 `.env*`、`.DS_Store`、浏览器状态、vault-style 敏感目录 |

## 5. P4 Discovery 必跑

在复制或选择目标工程后，先证伪假设，不凭印象开工。

```bash
find template -maxdepth 3 -type f | sort
cat template/package.json
rg -n "MkSaaS|mksaas|AI SaaS|credits|demo|lifetime|upgrade|Login|Get Started|Security|System Status|2024" template
rg -n "cdn.tailwindcss.com|Material Symbols|material-symbols|surface|on-surface" content/design/output
rg -n "官方合作伙伴|官方中文指南|包过|保过|通过率|题库命中率|首批持证团队" content content/design
git status --short
```

结果必须写进 `00-discovery.md`，不要只在终端里看过。

## 6. Required Decision Registers

P4 不是只写技术任务，还必须冻结这些决策。不能冻结的，必须进入 non-scope 或 Owner-blocked。

### 6.1 Route Scope Matrix

P4 必须声明 Phase 1 路由范围：

| Route | Default P4 status |
|---|---|
| `/` | IN_SCOPE |
| `/guide` | IN_SCOPE |
| `/bootcamp` | IN_SCOPE |
| `/enterprise` | IN_SCOPE |
| `/contact` | DECIDE：独立页或复用企业/订阅表单 |
| `/waitlist` | DECIDE：独立页或 Bootcamp section |
| `/blog` | DECIDE：首发隐藏或保留内容入口 |
| `/domains/*` | NON_SCOPE unless Owner promotes |
| `/scenarios/*` | NON_SCOPE unless Owner promotes |

### 6.2 Locale Strategy

P4 必须选择：

- `zh-only MVP`：默认推荐，隐藏英文入口，但可保留 en messages scaffolding。
- `zh + en visible`：需要完成英文文案审查和 hreflang/metadata 验证。

### 6.3 Forms Mode

P4 必须为每类表单选择实现模式：

| Form | Required decision |
|---|---|
| Newsletter | placeholder / Server Action / mail provider |
| Bootcamp waitlist | placeholder / Server Action / mail provider / CRM |
| Enterprise inquiry | must include eligibility fields + API consulting need |
| Contact | merge with enterprise inquiry or independent contact form |

### 6.4 Asset Manifest

P4 file-change plan 必须列出：

- Logo SVG source and target path.
- favicon source and target path.
- OG image status: generate now / placeholder / defer.
- Any public asset that must not be copied from Stitch.

### 6.5 Owner Decision Register

P4 必须把 `PENDING` 分三类：

| Class | Meaning | P5 behavior |
|---|---|---|
| Safe default | 可采用保守默认值 | P5 可执行 |
| Owner decision | 需要用户确认 | P5 前阻塞 |
| Non-scope | MVP 不做 | P5 隐藏或删除 |

## 7. {{PROJECT}} Correctness Properties

P4 至少要写入这些可验证属性：

| ID | Property |
|---|---|
| CP-01 Content source | 页面上线文案必须追溯到 `content/` 或 `content/_implementation/`，不得从 Stitch 截图临时抄英文 |
| CP-02 Token source | 页面颜色、字体、间距、边框只引用 `content/design/design-tokens.md` 映射后的命名 token |
| CP-03 Stitch isolation | `code.html` 只读参考；生产代码不得包含 CDN Tailwind、Material Symbols、MD3/surface token |
| CP-04 Shell single source | Navbar、Footer、Logo、{{BRAND_PARTNER_SIGNATURE}} 署名只能由共享 Shell 派生 |
| CP-05 Enterprise cleanup | 生产代码不得出现 `Login`、`Get Started`、`Security`、`System Status`、固定 `2024` |
| CP-06 Template purge | `MkSaaS`、`mksaas`、`AI SaaS`、`credits`、`demo`、`lifetime`、`upgrade` 等模板词 0 命中 |
| CP-07 Compliance lock | locked phrases 不得进入 messages、页面、metadata、OG 或结构化数据 |
| CP-08 Forms safe mode | Bootcamp 只做 waitlist；Enterprise 先资格甄别；不得公开自助支付 |
| CP-09 Responsive implementation | 虽然 P3B 不要求移动截图，P4/P7 必须验证 320px 不溢出、不横向滚动 |
| CP-10 Build gate | 实现后必须通过 lint/build/anti-slop/关键页面截图核验 |
| CP-11 Route scope | P5 只能实现 P4 route scope matrix 中的 in-scope 路由 |
| CP-12 Decision closure | 所有 `PENDING` 必须变成 safe default、Owner decision 或 non-scope |
| CP-13 Baseline isolation | P5 开工前必须有 Git baseline，保证实现 diff 可审计 |

## 8. P4 不应开始清单

以下任一项存在，不能进入 P5 实现：

- 目标工程目录未确定，或未完成 discovery。
- `messages-map`、`website-config-map` 中的 `PENDING` 项没有分类为 safe default / Owner decision / non-scope。
- Enterprise 旧词清理没有写进 file-change plan。
- Bootcamp 是否公开价格/支付仍未锁定。
- 表单方案未决定：仅前端占位、Server Action、邮件服务或 CRM。
- OG 图、favicon、Logo 资产落点未列入 file-change plan。
- Phase 1 route scope 未冻结。
- locale 策略未冻结。
- P5 前没有 baseline commit，且没有显式例外。
- Git 状态中出现 `.env*`、`.DS_Store`、浏览器状态、敏感资产 vault。
- P4 没有明确验证命令和通过标准。

## 9. P4 Completion Definition

P4 完成不是“写完五个文件”就算完成。必须满足：

- 五件套存在，且每件都有 Explicit Scope / Non-Scope。
- `00-discovery.md` 包含实际命令输出摘要，而不是假设。
- `01-requirements.md` 包含 route scope、locale strategy、forms mode、asset manifest。
- `02-file-change-plan.md` 精确到目标文件级别。
- `03-tasks.md` 每个任务能追溯到 requirement / correctness property / verification。
- `04-implementation-gate.md` 列出 no-go items、Owner decisions、negative assertions、viewport matrix。
- 用户确认 P4 Gate 后，才进入 P5。

## 10. Verification Matrix Required In P4

P4 gate 至少规划这些验证：

| Type | Required |
|---|---|
| Negative grep | template purge、Enterprise cleanup、locked phrases、Stitch pollution |
| Build | package manager install + lint + build |
| Visual | desktop screenshot for in-scope pages |
| Responsive | 320px / 768px / desktop viewport checks |
| Content | messages keys and content source trace |
| Compliance | locked phrases 0 命中；Enterprise eligibility present |

## 11. 与 P5 的边界

P4 只写规范，不改生产代码。P5 才做：

- 复制或初始化 `template/`。
- 替换 `messages/*.json` 或等价 i18n 文件。
- 改 `src/config/website.tsx` 或等价集中配置。
- 实现共享 Shell、页面组件、表单、SEO。
- 跑 Scan & Purge、lint/build、截图验证。

如果在 P4 发现模板不适合，不要硬改代码；先把“采用模板 vs 手写收敛”的决策写进 `04-implementation-gate.md`。
