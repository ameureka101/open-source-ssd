════════════════════════════ 三处「名不副实」的想象 ════════════════════════════
  ⚠① S1  「产品经理+交互师 agent 出 PRD+Figma」
       实为：HTML 蓝图 + 视觉门禁，无 Figma/原型/交互稿，无 PM/交互师分工
  ⚠② ④    「三类 CR（规范/业务/安全）」
       实为：单一「对抗验证」机制覆盖三类关注点（业务=proof/安全=guard/规范=FPF）
  ⚠③ S3    「端到端自动化 CI/CD」
       实为：CI 注释自述「Minimal CI gate…No release step」，CD 靠人工 Vercel

════════════════════════ 五维审计如何串成这张全景 ════════════════════════════
  三层地图审计 → 看「地图层」：导航在退步（总图过期/缺总楼层牌/缺统一门牌）
  拆卡审计     → 看「执行控制面」：拆卡/守门/续跑已成熟（553 任务卡）
  SDD 审计     → 看「契约层」：分层+反向推导是强项（10 层+FPF 证伪）
  loop 总结    → 看「循环使用」：8 专项演进（goal 内联→独立 GOAL 文件）
  编排审计(本图)→ 看「总编排」：机制在，但「两列并置的总图」仓库里不存在
  测试契约审计 → 看「测试金字塔」：下三层是契约（单元204/接口/集成），顶层空白（端到端零覆盖）
