第 2 站

双轨并行取证

左列 ∥ 右列 · 主会话补盲

把同一维度拆成「左列 + 右列」两个子面，各启动一个 Explore/取证 agent 并行跑；主会话不等，自己 grep / read 关键锚点复验 agent 断言。

Agent(左列子面) ∥ Agent(右列子面) ＋ 主会话自行验证

门禁维度例子

  • 左列 门禁侧（硬/软脚本、workflows、fail-closed）
  • 右列 经验管理侧（加/减/循环、分层、旗舰实证）

编排维度例子

  • 左列 S0→S5 研发生命周期
  • 右列 ①→⑤ Agent 执行流水线
关键纪律：agent 断言必须主会话复验——「agent 说 fail-closed，主会话 grep 到 L13/L202/L316 才算数」。

第 3 站

四维判定

优点+问题成对 · 带文件路径

把维度拆成 3-4 个判定子项，每个给 🟢/🟡/🔴 + 一句判断。每子项「已确认优点 + 确认问题」成对列出，优点必须带真实文件路径（≠空话），最后落到「现状判断」状态表 + 一句梯度结论。

框架回顾表 → 逐维优点/问题 → 现状判断 → 梯度结论

判定模板

  • 子面 A 🟢/🟡/🔴 一句判断
  • 子面 B …
  • 优点带路径 · 问题带后果

门禁·经验例

  • 硬门禁 🟢 fail-closed 全机械链路
  • 软门禁 🟢 覆盖面广靠人审
  • 经验加 🟢 三层分层 · 经验减 🟡 缺机械闸

第 4 站

找差距（增量价值）

名不副实 · 自评vs实态 · 引用没校验 · 写了没上岗

这是每次审计的增量价值所在——不是复述机制，而是揪出「写了却没有」的差距，并定 P 级。

四类差距找法 → P0/P1/P2 分级

四类差距

  • 名不副实 文档写的 vs 仓库实际有的
  • 自评 vs 实态 对照 harness 3.8/5.0
  • 被引用没校验 无时效校验（ENG-01 16 天）
  • 写了没上岗 17 proof 无全覆盖清单强制

实锤例（编排审计）

  • ⚠①「PM+交互师出 PRD+Figma」实为 HTML 蓝图
  • ⚠②「三类 CR」实为单一对抗验证
  • ⚠③「端到端 CI/CD」实为最小门禁无 release
核心：找「机制在但总图不存在」的缺口——差距不是没有机制，而是机制没被一张图收拢。

总编排图是罗盘 · 跨维度索引

把每个审计的「切面」写进总编排图「五维审计如何串成全景」段，与已有多份审计交叉引用（不重复），以判定基线（如 harness 3.8/5.0）作罗盘零点。

总编排图-两条管线一套逻辑-2026-08-28.txt → 各维度切面索引

六维罗盘（对照 harness 自评 3.8/5.0）

  • 地图层 🟡 导航在退步（总图过期/缺父级索引）
  • 执行控制面 🟢 拆卡/守门/续跑已成熟（553 任务卡）
  • 契约层 🟢 分层+反向推导是强项（10 层+FPF 证伪）
  • 循环层 🟢 8 专项演进（goal 内联→独立 GOAL）
  • 编排层 🟢 机制在，但总图仓库不存在 → 本图补缺
  • 门禁·经验层 🟢 硬门禁守底线 · 软门禁靠人审 · 经验减法缺机械闸

可复用 checklist

下次再来一个「再按前 N 份一致方法论审计 X」：六步管道不变，切面每次新换。直接套下面 checklist：

① claude-mem 回顾 → 看样板 ② 拆两子面 → 并行 agent → 补盲 ③ 四问判定 → 优点+问题成对 ④ 找差距 → 四类差距 → P 级 ⑤ 双份产物 → .md + .html + ASCII ⑥ 罗盘落盘 → 总编排图索引 + 关联

纪律：全程只读 · agent 断言主会话复验 · 结论落磁盘路径。

六份审计只是管道跑了六次留下的一组产物；管道本身才是这次沉淀的真正价值。
