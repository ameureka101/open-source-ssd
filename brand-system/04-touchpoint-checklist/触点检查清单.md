## 0. 使用原则

CCAF101 的品牌资产不是装饰素材，而是项目身份系统。任何站点、课程物料、文档和对外内容使用品牌资产时，必须满足以下原则：

- 只使用 `docs/brand/02-工程落地/output/` 中由脚本生成的资产。
- 不手工重画 The Beacon Owl，不临时改色，不添加盾牌、徽章、证书、奖章、学士帽、机器人、AI 脑或官方认证拟态元素。
- `Ameureka × CCAF101` 是对外署名基线；不得混淆 Ameureka 主品牌和 CCAF101 子品牌定位。
- 所有对外发布物仍受 `AGENTS.md §2` 约束，发布前必须人审。

## 1. Phase 1: Scan & Purge

站点代码建立或从模板复制后，先执行排异扫描，再做任何视觉开发。

### 1.1 模板幽灵资产

```bash
# mk-saas / 模板残留
rg -n "mksaas|mk-saas|saasfly|boilerplate|template" ccaf101-site/ public/ src/

# 默认外链图片
rg -n "(source|images)\\.unsplash\\.com|picsum\\.photos|placehold\\.co|placeholder" ccaf101-site/ public/ src/

# 旧 Logo / 默认图标
rg -n "logo\\.png|favicon\\.ico|apple-touch-icon|android-chrome" ccaf101-site/ public/ src/
```

处理规则：

| 发现项 | 处理 |
|---|---|
| 模板品牌名 | 替换为 `CCAF101` 或 `Ameureka × CCAF101`，按场景决定 |
| 默认 Unsplash / placeholder 图 | 删除或替换为项目自有图 |
| 默认 favicon / logo | 用 P3 输出资产替换 |
| 官方认证拟态图形 | 删除，不做替换 |

### 1.2 颜色污染扫描

```bash
# 绝对禁止：紫 / 蓝紫科技风
rg -n "(text|bg|border|from|to|via)-(purple|indigo|violet)-[0-9]" ccaf101-site/ src/

# 泛蓝紫渐变
rg -n "from-.*(purple|indigo|violet)|to-.*(purple|indigo|violet)|via-.*(purple|indigo|violet)" ccaf101-site/ src/

# 非保护区硬编码 HEX
rg -n "(bg|text|border)-\\[#" ccaf101-site/ src/ --glob "*.tsx" --glob "*.ts" \
  | rg -v "bootcamp|pricing|components/marketing"
```

处理规则：

| 类型 | 处理 |
|---|---|
| `purple-*` / `indigo-*` / `violet-*` | 删除或替换为语义 token |
| 通用组件硬编码 HEX | 提取为 `globals.css` 语义 token |
| 保护区硬编码 | 保留前必须有设计理由 |
| 功能绿 / 功能红 | 仅用于成功、错误、风险、阻断状态 |

## 3. Phase 3: Color Coding Decision Tree

新增组件或页面时按这个顺序判断：

1. 是否是 `/bootcamp` 或 `/pricing`？
   - 是：允许局部硬编码或更精确视觉控制，但必须有转化或层级理由。
   - 否：继续下一条。
2. 是否是功能状态？
   - 成功 / 已完成 / 正确：可用 `green-*`。
   - 错误 / 阻断 / 风险：可用 `red-*`。
   - 警告 / 注意：可用 `orange-*`，但不得冒充品牌琥珀。
3. 是否是 CTA？
   - 是：使用 `bg-brand hover:bg-brand-accent text-brand-foreground`。
4. 是否是通用组件？
   - 是：必须使用 `bg-background`、`text-foreground`、`bg-primary`、`text-primary-foreground`、`border-border` 等语义 token。
5. 是否出现 `purple-*` / `indigo-*` / `violet-*`？
   - 是：删除。CCAF101 禁止泛蓝紫科技风。

## 4. Phase 4: PR Review Gate

每次站点 PR 合并前运行以下检查。

```bash
# 1. 模板残留
rg -n "mksaas|mk-saas|saasfly|boilerplate|template" ccaf101-site/ public/ src/

# 2. 幽灵外链图片
rg -n "(source|images)\\.unsplash\\.com|picsum\\.photos|placehold\\.co|placeholder" ccaf101-site/ public/ src/

# 3. 禁用色系
rg -n "(text|bg|border|from|to|via)-(purple|indigo|violet)-[0-9]" ccaf101-site/ src/

# 4. 非保护区硬编码 HEX
rg -n "(bg|text|border)-\\[#" ccaf101-site/ src/ --glob "*.tsx" --glob "*.ts" \
  | rg -v "bootcamp|pricing|components/marketing"

# 5. 双品牌署名
rg -n "Ameureka.*CCAF101|CCAF101.*Ameureka" ccaf101-site/ src/ content/

# 6. 认证边界高风险词
rg -n "官方授权|官方认证机构|官方颁发|包过|保过|直供|纯内资" ccaf101-site/ src/ content/
```

PR 合并条件：

| 检查 | 要求 |
|---|---|
| 模板残留 | 零命中，或命中项有明确保留理由 |
| 幽灵外链图片 | 零命中 |
| 禁用色系 | 零命中 |
| 非保护区硬编码 HEX | 零命中，或提取为 token |
| 双品牌署名 | 对外页必须能确认署名边界 |
| 认证边界高风险词 | 命中即人工复核 |

## 5. 保护区域白名单

| 区域 | 允许 | 不允许 |
|---|---|---|
| `/bootcamp` | 局部 `bg-brand`、`bg-brand-muted`、训练营转化图形 | 官方认证拟态、徽章/证书伪装、大面积琥珀铺底 |
| `/pricing` | 局部硬编码用于套餐层级、CTA 和对比表 | 紫蓝渐变、夸大承诺、与 Ameureka B 端价格段混用 |
| `components/marketing/` | 局部高保真视觉实现 | 把营销硬编码扩散到通用组件 |

保护区说明：

- 保护区不是豁免区，只是允许为了转化和层级做更精确的视觉控制。
- 保护区内的模式不得外溢到 Navbar、Footer、Form、Card、Docs 等通用组件。
- 保护区内所有对外话术仍需遵守 CPN 合规边界和认证事实准确性。

## 6. 资产使用禁区

| 禁区 | 原因 |
|---|---|
| 给 The Beacon Owl 加盾牌、徽章、证书或奖章 | 容易暗示官方认证颁发 |
| 给 The Beacon Owl 加眼镜 | token101 的专属识别特征 |
| 给 The Beacon Owl 加灯泡 | Ameureka Bulb Bot 的专属识别特征 |
| 把 Beacon Amber 大面积铺满页面 | 破坏 B&W 90% / Amber 7% 配比预算 |
| 手工修改 PNG 像素 | 破坏 Code-Is-Truth |
| 使用非脚本生成的 favicon | 破坏可追溯性 |
